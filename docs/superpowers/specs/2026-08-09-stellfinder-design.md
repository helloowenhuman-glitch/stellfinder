# Stellfinder 제품 기획서

## 1. 프로젝트 개요

Stellfinder는 스텔라이브 관련 특별 행사를 한곳에 모아 월간 캘린더로 보여 주는 팬 서비스다. 공식 공지는 여러 채널과 게시물에 흩어져 있어 공연, 굿즈 판매, 팝업스토어, 예매 마감 같은 중요한 일정을 놓치기 쉽다. Stellfinder는 이를 매일 수집하고 일정 형태로 정리해, 사용자가 특정 월의 행사를 빠르게 확인하도록 돕는다.

### 목표

- 스텔라이브의 특별 행사를 월간 단위로 한눈에 확인하게 한다.
- 공식 출처 링크를 함께 제공해 일정의 근거를 투명하게 보여 준다.
- 멤버별 색상으로 관련 인물을 즉시 구별하게 한다.
- 정기 방송 일정은 제외해 캘린더가 과도하게 복잡해지는 것을 막는다.

## 2. MVP 범위

### 포함하는 일정

- 콘서트, 공연, 팬미팅, 쇼케이스
- 팝업스토어, 전시, 오프라인 행사
- 굿즈, 음원, 앨범의 공개, 예약 판매, 판매 마감, 배송 시작
- 브랜드, 게임, 플랫폼 등 외부 콜라보
- 예매, 응모, 사전 예약, 이벤트 참여의 시작일과 마감일
- 강지 관련 특별 행사

### 제외하는 일정

- 멤버의 정기 라이브 방송 및 일반 방송 스케줄
- 출처가 확인되지 않는 팬 커뮤니티의 제보
- 행사와 무관한 일반 콘텐츠 업로드

### 첫 출시 화면

- Stellfinder 웹사이트 내부의 월간 캘린더 화면만 제공한다.
- Google Calendar, Apple 캘린더 등의 외부 연동과 구독 기능은 MVP 범위에서 제외한다.

## 3. 사용자 경험

### 월간 캘린더

- 상단 중앙에 `YYYY.MM` 형식의 현재 월을 표시한다.
- 좌우 화살표로 이전 달과 다음 달로 이동한다.
- 일요일부터 토요일까지 7열 그리드로 날짜를 배치한다.
- 일요일 날짜는 빨간색, 토요일 날짜는 파란색으로 표시한다.
- 일정은 날짜 칸 안에 가로 바로 표시한다.
- 하루짜리 일정과 기간 일정 모두 일정 바의 양 끝을 둥글게 표시한다.
- 기간 일정은 시작일부터 종료일까지 각 날짜 칸을 이어 가로 바로 표시한다.
- 일정이 많은 날에는 우선순위가 높은 일정부터 노출하고, 남은 일정 수를 알 수 있는 확장 동작을 제공한다.

### 필터

상단 필터에서 다음 항목을 선택할 수 있다.

- 전체
- 공연
- 굿즈
- 콜라보
- 오프라인

필터는 복수 선택이 아니라 한 번에 하나의 행사 유형을 보여 주는 방식으로 시작한다. `전체`는 모든 일정을 보여 준다.

### 일정 상세

사용자가 일정 바를 선택하면 다음 정보를 표시한다.

- 일정명
- 행사 유형
- 시작 일시와 종료 일시 또는 기간
- 관련 멤버 또는 단체
- 장소 또는 온라인 진행 정보(공지에 있을 때만)
- 일정 설명 요약
- 공식 공지 원문으로 이동하는 링크
- 등록 상태: 자동 확인 또는 검수 필요

## 4. 디자인 원칙

참고한 캘린더 화면의 간결한 월간 그리드, 얇은 회색 구분선, 넉넉한 흰 여백을 유지한다. 디자인의 핵심 차별점은 멤버별 색상과 둥근 일정 바다.

- 페이지 배경과 날짜 칸은 흰색 중심으로 유지한다.
- 일정 바는 각 기준색의 밝은 틴트 배경을 사용한다.
- 일정 제목, 테두리, 작은 상태 표시는 해당 대상의 기준색을 사용한다.
- 일정 바의 모서리는 8~10px 정도로 둥글게 처리한다.
- 여러 멤버가 참여하는 행사라도 무지개색 또는 다중 그라데이션을 사용하지 않는다. 단체 색상으로 통일해 작은 화면에서도 제목을 읽기 쉽게 한다.
- 색상만으로 행사 의미를 전달하지 않는다. 제목과 상세 정보에도 멤버 및 행사 유형을 텍스트로 표시한다.

### 색상 적용 규칙

- 일정에 관련 인물이 한 명이면 해당 인물의 색상을 적용한다.
- 강지 단독 관련 일정에는 강지 색상을 적용한다.
- 스텔라이브 전체 또는 두 명 이상이 함께하는 일정에는 스텔라이브 단체 색상을 적용한다.
- 멤버 색상이 매우 밝을 때는 제목 글자색을 충분히 진하게 조정해 읽기 쉬워야 한다.

## 6. 행사 데이터 기준

모든 일정은 아래 정보를 갖는다.

| 필드 | 설명 |
| --- | --- |
| `title` | 캘린더와 상세 화면에 표시할 행사명 |
| `category` | 공연, 굿즈, 콜라보, 오프라인 중 하나 |
| `startAt` | 시작 일시. 시간이 없으면 시작 날짜만 저장 |
| `endAt` | 종료 일시. 단일 일정이면 비워 둘 수 있음 |
| `allDay` | 시간 미상 또는 종일 일정 여부 |
| `participants` | 관련 멤버, 강지, 또는 스텔라이브 단체 |
| `displayColor` | 위 색상 규칙으로 결정된 기준색 |
| `location` | 장소 또는 온라인 진행 정보. 없는 경우 비움 |
| `summary` | 공식 공지를 바탕으로 한 짧은 설명 |
| `sourceUrl` | 공식 원문 URL |
| `sourceChannel` | `official-site` 또는 `official-x` |
| `sourcePublishedAt` | 원문 게시 시각 |
| `status` | `verified` 또는 `needs-review` |
| `externalId` | 중복 판별을 위한 원문 URL 또는 채널별 고유 식별자 |

## 7. 자동 수집과 검수 흐름

### 수집 대상

- 스텔라이브 공식 웹사이트의 공지
- 스텔라이브 공식 X 게시물

### 매일 실행 흐름

1. 하루에 한 번 공식 웹사이트와 공식 X의 신규 게시물을 AI 기반 인터넷 검색으로 찾는다.
2. 각 게시물에서 행사명, 날짜와 시간, 기간, 장소, 행사 유형, 관련 인물을 추출한다.
3. 정기 방송 일정과 행사와 무관한 게시물을 제외한다.
4. 기존 일정의 원문 URL, 제목, 날짜를 비교해 중복 등록을 막는다.
5. 날짜와 행사 성격이 명확하고 공식 원문 링크가 있는 일정은 `verified` 상태로 등록한다.
6. 날짜가 모호하거나 행사 여부를 확신할 수 없으면 `needs-review` 상태로 저장한다.
7. 이미 등록한 행사에 날짜, 장소, 판매 기간 등의 변경 공지가 나오면 기존 일정을 수정하고 원문 출처를 추가한다.

### 안전 기준

- 공식 출처 링크가 없는 검색 결과만으로 공개 일정을 만들지 않는다.
- AI가 추정한 날짜는 공식 원문에서 다시 확인할 수 있을 때만 공개한다.
- 출처와 추출 시각을 기록해 잘못된 정보를 나중에 수정할 수 있게 한다.

## 8. 개발 단계

### 1단계: 행사 데이터와 관리 기반

- 행사 데이터 구조를 만들고 수동으로 예시 일정을 등록한다.
- 멤버, 강지, 단체 색상 규칙을 데이터에 적용한다.
- 단일 일정과 기간 일정이 모두 저장되는지 확인한다.

**완료 기준:** 예시 일정이 월간 캘린더에 날짜와 기간에 맞게 표시된다.

### 2단계: 월간 캘린더 화면

- 이전 달과 다음 달 이동을 구현한다.
- 행사 유형 필터를 구현한다.
- 둥근 일정 바, 멤버별 색상, 단체 색상을 적용한다.
- 일정 선택 시 상세 정보를 표시한다.

**완료 기준:** 참고한 시안과 같은 정보 구조에서 일정의 기간, 유형, 관련 인물을 구분할 수 있다.

### 3단계: 공식 공지 자동 수집

- 매일 실행되는 수집 작업을 만든다.
- 공식 웹사이트와 공식 X에서 새 공지를 검색한다.
- 행사 데이터를 추출하고 중복을 제거한다.
- 확실한 일정은 자동 등록하고 모호한 일정은 검수 대기로 저장한다.

**완료 기준:** 새 공식 공지가 등록된 뒤 다음 수집 실행에서 중복 없이 일정 후보가 생성된다.

### 4단계: 운영 검수와 보완

- 검수 대기 일정을 확인하고 공개 또는 제외한다.
- 변경·취소 공지를 기존 일정에 반영한다.
- 누락된 행사와 잘못 분류된 행사를 기록해 수집 규칙을 개선한다.

**완료 기준:** 공식 공지 링크를 통해 모든 공개 일정의 근거를 확인할 수 있다.

## 9. MVP 완료 조건

- 웹사이트 안에서 어떤 달의 특별 행사를 월간 단위로 볼 수 있다.
- 정기 방송 일정이 표시되지 않는다.
- 행사 유형별 필터가 동작한다.
- 멤버, 강지, 단체 일정이 확정한 색상 규칙으로 구분된다.
- 기간 일정의 양 끝이 둥근 가로 바로 표시된다.
- 각 일정에서 공식 출처로 이동할 수 있다.
- 자동 수집 결과의 출처와 검수 상태를 확인할 수 있다.

## 10. 데이터 보관과 용량 안전 기준

- 공개된 행사 정보, 공식 원문 링크, 수정·취소 이력은 기본적으로 보관한다.
- 공지 이미지, 원문 HTML 전체, AI 검색 결과 전문은 저장하지 않는다.
- 수집했지만 공개하지 않은 후보는 90일 뒤 삭제하고, 수집 실행 로그는 30~90일 뒤 삭제한다.
- Supabase 데이터베이스 전체 사용량이 480MB를 초과하면, 가장 오래된 행사부터 순서대로 삭제해 사용량을 480MB 미만으로 낮춘다.
- 삭제 작업은 일일 수집 작업이 시작되기 전에 실행하며, 삭제한 행사 수와 삭제 기준 날짜를 운영 로그에 남긴다.
